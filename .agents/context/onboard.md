# Agent Onboarding & Self-Extension Guide

Welcome, Agent! You are working in the **ClearCutt Verify** repository.

To ensure you can operate here with maximum efficiency, zero regressions, and full synchronization with other AI tools, this repository implements a **Unified, Harness-Agnostic Agent DX & Memory System**.

Before starting any task or writing any code, please review this guide.

---

## 1. The Core Rules of Engagement

Every agent working in this repository MUST adhere to the following contract:

1. **Short-Term Context RAM (`.agents/context/active_context.md`):**
   * `.agents/context/active_context.md` is local, ignored working state. It must not be committed.
   * If the file exists, read it at the start of your turn to restore active goals, recent errors, and work progress.
   * During long-running work, update it with current status, modified files, active blockages/test failures, and next steps.
   * If you need a starting template, copy `.agents/context/active_context.example.md`.

2. **Long-Term Lessons ROM (`.agents/context/lessons_learned.md`):**
   * **Before making changes:** Read `.agents/context/lessons_learned.md` to check for known anti-patterns, environment bugs, and design constraints specific to this monorepo.
   * **Self-Improving Memory:** If you struggle with a bug for more than two turn cycles, or if you discover a subtle architectural constraint, you MUST write down a new lesson in `.agents/context/lessons_learned.md` to ensure future agents do not repeat the mistake.

3. **No Direct Config Edits:**
   * Never modify generated files such as `.cursorrules`, `.claudeprompt`, `.windsurfrules`, `.github/copilot-instructions.md`, or `.vscode/tasks.json` directly.
   * Instead, modify the centralized source files in `.agents/context/` and compile them using `make agent-sync` (which runs `bash .agents/sync.sh`).
   * Root-level harness files are ignored local outputs; `.github/copilot-instructions.md` is the committed generated target for GitHub Copilot.

## 3. How to Self-Bootstrap / Extend for a New Harness

If you are using an AI harness that is **not** currently generated by `.agents/sync.sh` (for example, Cody, Aider, or a custom system):

### Step A: Locate your harness configuration file
Identify the file name and directory structure your AI harness uses to read project instructions (e.g., `.codyrules`, `.aider.conf.yml`, or similar).

### Step B: Modify `.agents/sync.sh`
Open `.agents/sync.sh` and locate the compilation block. Add a new compilation target block to generate your config file. For example:

```bash
# Compile My Custom Harness Rules
echo "==> Compiling .mycustomrules..."
cat << 'EOF' > .mycustomrules
# Custom Harness Header
EOF
cat .agents/context/instructions.md >> .mycustomrules
cat .agents/context/architecture.md >> .mycustomrules
cat .agents/context/lessons_learned.md >> .mycustomrules
```

### Step C: Compile and Commit
1. Run `make agent-sync` (or `bash .agents/sync.sh`) to generate your native configuration.
2. Verify that your harness now detects and respects the generated instructions.
3. Commit the updated `.agents/sync.sh` and add your generated configuration file to the `.gitignore` if it contains absolute paths or local state, or commit it if it is safe.
